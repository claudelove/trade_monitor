[대시보드 열기](https://claudelove.github.io/trade_monitor/) · [GitHub Pages 배포·사용 안내](docs/DEPLOYMENT.md) · [현재 상태/새 채팅 인계](docs/HANDOFF.md)

별도 서버 없이 GitHub Pages로 프로토타입을 확인하도록 전환했습니다. Pages는 공개 스냅샷과 브라우저 백테스트를 제공하고 Python 수집은 GitHub Actions에서 실행합니다. GitHub Pages 배포와 HTTP 응답을 확인했으며 상세 상태는 인계 문서에 기록합니다. 인증키는 소스·페이지에 포함하지 않고 Actions secrets로만 전달합니다.

## 실행

Python 3.12 이상을 권장합니다. Node는 프런트엔드 테스트에만 필요합니다.

```bash
cd /workspace/trade_monitor
python -m venv --system-site-packages .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/uvicorn monitor.app:app --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 기존 수집 DB가 있으면 실데이터가 바로 표시됩니다. 빈 설치에서는 **데이터 수집**을 실행하거나 우측 상단에서 **합성 데모**를 선택합니다. 새 가상환경에서는 `--system-site-packages`를 생략해도 됩니다.

`DART_API_KEY`는 런타임 환경 변수로 전달합니다. 키를 소스·웹 입력 폼·브라우저 저장소·Git에 넣지 마세요. 현재 환경에는 이미 설정되어 있습니다. 키 없이도 데모·가격·뉴스 경로는 동작하며 DART만 실패 상태로 표시합니다.

CLI 수집 예:

```bash
.venv/bin/python -m monitor.cli --start 2026-10-01 --end 2026-11-03 --tickers 005930,000660,035420,005380,105560,069500
```

## 화면과 기능

- **이벤트 모니터:** 기업·종목·공시 검색, 전략·검토 상태 필터, 최근 종가·등락률, CSV 내보내기. 요약·피드·차트/뉴스 위젯을 켜거나 끄고 순서를 바꿀 수 있습니다.
- **공시 상세:** DART 원문 링크, 전략 가설·검토 항목, 이벤트 전후 가격 차트, D+1/3/5/10/20 수익률과 KODEX 200 대비 초과수익. 기업명·이벤트 전후 기간으로 관련 뉴스 후보를 추가 수집할 수 있습니다.
- **전략 라이브러리:** 실적·가이던스, 자사주·환원, M&A·공개매수, 자본조달·희석, 지배구조·특수상황. 키워드 기반 검토 분류이며 성공 확률이나 방향성 매매 신호가 아닙니다.
- **공개매수 시나리오:** 현재가·종결가·실패가·종결 확률·기간·왕복 비용을 입력해 스프레드·단순 연율·확률가중 기대값을 계산합니다. 실제 거래 조건을 자동 추출한 값이 아닙니다.
- **백테스트 랩:** 이벤트 종류·보유 기간·비용·전일 거래대금 추정 하한·공시 기간을 지정합니다. 체결 내역, 누적 순수익률, 일봉 종가 기준 MDD, 승률, 제외 사유와 CSV를 제공합니다.
- **관심 이벤트:** 브라우저 저장소에 관심 이벤트를 보관합니다. 서버 사용자 계정 간 동기화는 없습니다.
- **데이터 연결:** 공급자별 성공·실패·표본 잘림과 캐시 사용을 확인합니다. 갱신은 수동 실행입니다.

## 데이터 출처와 현재 범위

| 데이터 | 제공 경로 | 범위 / 제약 |
| --- | --- | --- |
| 공시 | Open DART `list.json` | 유가증권시장(`corp_cls=Y`), 회당 최대 500건·최대 120일. 기간을 나누어 누적 수집 가능 |
| 가격 | pykrx `get_market_ohlcv_by_date(adjusted=True)` | **pykrx 내부 NAVER 경로**, 선택 종목 최대 12개 수정 일봉. KRX 직접 인증 성공을 뜻하지 않음 |
| 뉴스 | Google News RSS | 검색당 최대 30건, 누적 최대 300개 링크. 제목·발행시각·언론사·원문 링크, 기사 본문 미수집 |
| 벤치마크 | `069500` KODEX 200 | ETF 가격수익률 기준. KOSPI 지수 총수익률과 다름 |

일봉에 거래대금이 없으면 `종가 × 거래량`을 **추정치**로 저장하며, 거래대금 필터도 이 추정치를 사용합니다. NAVER 수정주가 조정 방식·기업행동 반영은 별도 검증 대상입니다. 공시와 가격은 종목코드로 연결하고, 뉴스는 기업명·검색 기간을 이용한 관련 후보입니다. 뉴스와 이벤트의 인과관계나 감성은 자동 판정하지 않습니다.

공시 접수번호, 가격의 종목코드·거래일, 뉴스 URL로 누적 중복 제거합니다. 공급자 실패 시 이전 데이터를 유지하고 마지막 성공 시각을 표시합니다. 공시·가격 원천은 공급자 수정에 따라 바뀔 수 있습니다. 현재 DB는 과거 버전을 모두 보존하는 point-in-time 데이터베이스가 아닙니다.

## 백테스트 해석

1. DART 목록에는 접수 시각이 없어 접수일 23:59:59 KST 이후에만 사용 가능한 것으로 처리합니다. 공시일 당일에는 진입하지 않습니다.
2. 이후 거래 가능한 일봉의 시가로 진입하고, 설정한 종목 거래일 수만큼 보유해 종가에 청산합니다. 미래 가격이 부족하면 거래를 만들지 않습니다.
3. 한 번에 현금 100%를 사용하는 롱 포지션 하나만 유지합니다. 실제 진입일 순으로 처리하고 겹치는 이벤트는 제외합니다. 매수·매도마다 편도 비용을 적용합니다.
4. 유동성 필터는 진입 **전일** 거래대금/추정치를 사용합니다. 정정공시는 기본 제외합니다. 거래정지 봉을 포함한 보유 구간은 제외합니다.
5. MDD는 체결 시점 사이의 일봉 종가 평가액까지 계산합니다. 장중 낙폭이나 부분 체결은 모형에 없습니다.

현재 표본은 선택 종목·수집된 공시에 한정되므로 생존편향과 선택편향을 통제하지 못합니다. 수정주가와 별도로 배당 현금흐름을 더하지 않습니다. 실적 컨센서스, 서프라이즈, 공매도 가능 여부·대차료, 시장 충격, 거래정지 후 실제 체결 가능성, 포트폴리오 위험 한도는 추가 연구가 필요합니다. 공시 분류별 롱온리 이벤트 연구 결과를 해당 헤지펀드 전략 전체의 성과로 해석하면 안 됩니다.

## 확장 구조

```text
monitor/providers/  DART · RSS · pykrx 수집, DailyPriceProvider/Bar 계약
monitor/strategies.py  전략 규칙·연구 가설·검토 항목 레지스트리
monitor/store.py    SQLite 누적 저장, 실패 공급자 캐시 보존
monitor/analytics.py  이벤트 연구·체결·일봉 평가 독립 계산
monitor/app.py      FastAPI 웹/API, 수집 동시 실행 제한
monitor/cli.py      서버와 별도로 실행 가능한 수집 명령
web/               빌드 없는 ES 모듈 UI, 위젯 레지스트리
```

증권사 가격 어댑터는 공통 `Bar` 형식을 반환하도록 연결합니다. 실시간 체결·호가는 일봉과 다른 시각 정밀도·장 상태·중복 제거 계약이 필요합니다. 새 전략은 레지스트리에 분류·검토 항목을 추가하고 별도의 체결/분석 모델을 구현할 수 있습니다. 단순히 M&A 태그를 붙였다고 합병차익거래 체결 모델이 생기는 구조는 아닙니다.

현재는 개인용 단일 프로세스 구성입니다. 다중 사용자·다중 워커로 확장할 때는 수집 작업 큐, 사용자별 권한·관심 목록, PostgreSQL 시계열/이벤트 테이블로 이전해야 합니다. 프로세스 안에서 수집을 실행하므로 `--workers 1`을 유지합니다. pykrx 호출은 별도 프로세스로 분리해 80초 제한을 둡니다.

## API

- `GET /api/snapshot?mode=live|demo`
- `GET /api/event/{id}?mode=live|demo`
- `POST /api/event/{id}/news` — 실데이터 이벤트의 기업·기간 뉴스 검색
- `POST /api/refresh` — `start`, `end`, `tickers`, `query`
- `POST /api/backtest` — `mode`, `strategy`, `holding`, `cost_bps`, `min_value`, `start`, `end`
- `GET /api/health`, OpenAPI `/docs`

## 배포 준비

Python 서버와 정적 UI를 하나의 FastAPI 서비스로 배포하도록 `Dockerfile`과 `compose.yaml`을 제공합니다. `DART_API_KEY`, `MONITOR_PASSWORD`를 환경/시크릿 관리 기능으로 전달한 뒤 실행합니다.

```bash
docker compose up --build -d
```

Compose는 비밀번호 설정을 요구하며 포트는 호스트의 `127.0.0.1:8000`에만 연결합니다. 기본 인증 사용자명은 `research`이고 `MONITOR_USERNAME`으로 변경할 수 있습니다. 외부 접속에는 TLS 리버스 프록시/관리형 HTTPS와 영속 볼륨을 연결하세요. 비밀번호를 브라우저 JS에 넣지 않습니다. 단독 로컬 실행은 `MONITOR_PASSWORD`를 생략할 수 있습니다.

Docker/복구 검증과 실제 배포 상태는 [작업 인계](docs/HANDOFF.md)에 기록합니다. 현재 미리보기 배포는 GitHub Pages를 사용합니다. Render 안내는 docs/DEPLOYMENT_RENDER.md에 보존합니다. Python FastAPI 서버를 운영할 수 있는 호스팅이 필요합니다. Sites의 Workers 런타임만으로 Python 수집기를 그대로 운영할 수는 없습니다.
