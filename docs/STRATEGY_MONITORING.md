# 전략 중심 모니터링

2026-11-04 사용자 지시: 운용 검토는 포트폴리오/전략 중심, 마켓만 종목 티커 중심이다. 비공개 엔진 원본 계좌/실행 계약과 실행 소유권은 유지한다.

## 워크스페이스와 선택

- STRATEGY 기본 4패널: PERF 성과, HOLD 보유 구성, RISK 노출/집중도, EXEC 체결/비용.
- 추가 패널: ATTR 전략 기여도, CORR 전략 간 동행/중복 보유, HEALTH 보고/데이터 상태, 실행 원장, 코드 식별, 계좌 장부.
- PORTFOLIO는 현재 엔진의 계좌 실행 단위다. 별도 가상 포트폴리오 계층을 만들지 않는다. 단일 실행 파일은 단일 전략으로 표시한다.
- 여러 엔진 결과 파일을 현재 탭에 읽어 포트폴리오를 전환한다. 같은 계좌/실행 ID를 다시 열면 그 파일의 표시 상태를 교체한다. 과거 파일과 최신 파일을 자동 병합하지 않는다.
- STRATEGY 선택이나 기여도 행 선택은 전략 패널 전체를 갱신한다. 자식 결과 없는 계좌 파일은 전략별 장부 행만 선택 가능하며 상세/분석 원천은 미보고다.
- MARKET 기본 4패널: 종목 표, 가격, 뉴스, 공시. 종목은 이 공간에서만 공통 선택한다. 공개 시장 스냅샷과 선택 전략 저장 봉은 SOURCE로 명시적으로 바꾼다. 보유 종목에서 마켓 상세로 이동하면 해당 실행 저장 봉을 사용하며 공개 시세로 대체하지 않는다.
- 두 공간의 창 배치는 서로 다른 localStorage 키를 사용한다. 포트폴리오/전략 선택·결과·파일 속 종목은 탭 메모리에서만 유지한다. 새로고침하면 개인 결과는 해제된다.

메뉴/명령으로 패널을 열고 패널별 기능 선택·최대화/최소화/닫기·배치 편집을 사용한다. PERF/HOLD/RISK/ATTR/CORR/HEALTH, MKT/GP/TOP/FIL, ORD/CODE 관련 기존 명령을 제공한다. 조회 기능이며 전략 실행/주문을 하지 않는다.

## 참고한 공개 모니터링 자료

기관의 비공개 운용 구현을 복제했다고 주장하지 않는다. 아래 공개된 알고리즘 운용/포트폴리오 모니터를 참고해 현재 데이터로 가능한 진단을 구성했다.

- [QuantConnect live results](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/results): 성과/낙폭·주문 이벤트·로그를 함께 조회하는 구성.
- [IBKR PortfolioAnalyst dashboard](https://www.ibkrguides.com/orgportal/performanceandstatements/pa_viewingaccountperformance.htm): 계좌 선택과 보유·성과·활동·위험 위젯 구분.
- [IBKR concentration](https://ibkrguides.com/advisorportal/performanceandstatements/pa-concentration.htm): 롱/숏 노출과 집중도 구분.

이 자료들이 아래 앱의 계산식을 표준으로 보증하는 것은 아니다. 계산/누락 정책은 다음과 같다.

## 지표 정의와 원천

| 패널/지표 | 정의 | 원천/한계 |
| --- | --- | --- |
| NAV·계좌/전략 PnL | 계좌 summary/전략 curve 및 기여도 행 | 엔진 보고 값, 독립 결과 재합산 없음 |
| 관측 NAV 변화 | 마지막 NAV / 초기 자본 - 1; 초기 자본 없으면 첫 관측 NAV | 화면 진단. 입출금 보정 TWR/MWR 아님 |
| 낙폭 | NAV / 관측 최고 NAV - 1 | 화면 계산. 초기 자본이 있으면 최초 peak에 포함해 초기 손실 보존 |
| 관측 변동성 | 최근 최대 20개 인접 NAV 변화율의 표본 표준편차 | 최소 2개 유효 변화 필요. 비양수 NAV/잘못된 간격 포함 시 미보고. 연율화/Sharpe 추정 없음 |
| 보유 명목 | 부호 있는 수량 × 같은 평가 시각 저장 종가 × 엔진 상품 multiplier | 화면 계산. 가격/승수 누락 시 미보고. 이전 시각 가격을 채우지 않음. legacy는 KRW 외부 평가액만 사용 |
| Gross/Net | 절대 명목 합/NAV, 부호 있는 명목 합/NAV | 전체 평가 커버리지와 양수 NAV 필요. 엔진 보고 Gross와 화면 계산치를 구분 |
| Top1/Top5 | 절대 명목 합 대비 최대 1개/상위 5개 비중 | 레버리지/NAV 비중과 다름. 평가 불완전/절대 노출 0이면 미보고 |
| HHI | 절대 명목 비중 제곱합 | 집중도 진단. 리스크 정책/한도 위반 판정 아님 |
| 전략 기여도 | 계좌 strategies의 pnl/contribution_pp | 엔진 보고 KRW/%p를 그대로 표시. Brinson/factor attribution 아님 |
| 수량 체결률 | 주문 ID별 체결 절대 수량 합 / 전체 주문 절대 수량 합 | 고유 ID·수량·체결 귀속 필요. 누락/중복/초과/미등록 체결이면 미보고. 상태 건수와 구분 |
| 수수료/슬리피지 | 체결 fee/slippage 합계 | 모든 체결이 보고한 경우에만 합산. 진단용이며 PnL에서 다시 차감하지 않음 |
| 전략 동행 | 동일 시작/종료 시각 구간의 NAV 변화율 Pearson 상관 | 최소 3개 공통 구간, 0이 아닌 분산 필요. 앞 값 채우기 없음. 행렬 최대 12전략, 선택 전략 우선·표시 수 명시 |
| 중복 보유 | 두 전략 이상에서 0이 아닌 수량을 보고한 종목 | 보유 보고 커버리지 표시. 순포지션/계좌 위험을 임의 계산하지 않음 |
| 보고 상태 | 계좌 상태·updated_at·평가 시각·데이터 식별·커버리지 | 오래된 running은 15초 기준 파일 갱신 경고. 시장 freshness/실시간 worker heartbeat와 구분 |

섹터·베타·VaR·스트레스·호가 대비 체결비용·실제 주문 지연·증권사 대사는 원천/모형 미연결이다. 미보고를 0이나 정상으로 바꾸지 않는다. 차트 x축은 동일 관측 간격이며 실제 경과 시간에 비례하지 않는다.

## 예시·테마·검증

합성 분석 예시는 버튼을 눌러야만 열린다. 3개 합성 전략을 담은 자체 UI용 보고 레코드이며 실제 백테스트·매매 전략·성과가 아니다. 공개 코드에는 합성 생성기만 있고 개인 엔진 결과는 포함하지 않는다. 배너에 SYNTHETIC ANALYSIS를 표시한다.

테마는 일반 시스템 글꼴을 유지하고 검정 바탕, 더 선명한 주황 탐색/기능 헤더, 황색 핵심 수치/성과 선, 청록 상관/노출, 녹색/적색 방향을 사용한다. 숫자에 보이는 색은 운영 승인이나 전략 성공 확률이 아니다.

분석 코드는 web/strategy-analysis.js, 표현은 strategy-ui.js, 합성 예시는 analysis-example.js다. tests/strategy-analysis.mjs는 초기 손실·비양수 NAV·부호 있는 선물 노출·누락 명세/시점·체결 ID/부분 체결·동일 구간 상관·원본 불변을 검증한다. 기존 창/계약/Pages 검사와 실제 브라우저 선택/배치/모바일/메모리 격리 확인을 함께 수행한다.
