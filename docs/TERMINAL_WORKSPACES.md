# 종합 모니터링 터미널

이벤트 트레이딩은 FILINGS와 외부 전략 실행 중 한 사용 사례다. 기본 화면은 시장·종목·뉴스·외부 실행 현황을 함께 조회한다. 검정/회색·일반 시스템 글꼴·주황 탐색 포인트·테두리 없는 표/패널을 사용한다. Bloomberg의 명령/연결된 화면 구성과 사용자가 지정한 비공개 레퍼런스를 참고했고 비공개 코드/전문/전략은 공개 저장소에 복사하지 않았다.

## 화면과 명령

| 화면 | 명령 | 실제 데이터/기능 |
| --- | --- | --- |
| OVERVIEW | OV | 종목 표본, 선택 종목 캔들, 뉴스, 선택 실행 요약, 원천 상태 |
| MARKET | MKT | 수집 종목 일봉 표; 전체 시장 통계 아님 |
| SECURITY | GP [SYMBOL] | 선택 종목 캔들, 기업명 제목 매칭 뉴스, 종목코드 일치 공시 |
| NEWS | TOP | 뉴스 제목/매체 검색, 원문 링크, 최대 100건 표시 |
| FILINGS | FIL | 공시 유형/검색/관심 저장, 기존 가격·원문 상세 |
| EXECUTION | ORD | 기존 외부 실행 지표·포지션·주문·체결·평가액·로그 |
| RISK | RISK | 선택 실행의 외부 보고 상태·한도와 평가액 이력 |
| STRATEGY | STRAT | 코드 메타데이터, 결과 파일 열기, 관측 계약 |
| ACCOUNT | ACC | 미연결 상태. 계좌 장부 계약/대사 연결 필요 |
| DATA | DATA | 공급자 상태·현재 범위·수집 제한 |
| SAVED | SAVED | 저장한 공시 |

`/`로 명령창, 1–9로 앞의 9개 화면에 이동한다. 입력창/버튼/다이얼로그 조작 중 숫자는 단축키로 가로채지 않는다. HELP는 도움말이다. REFRESH는 저장된 상태 재조회이며 데이터 수집/실행/주문이 아니다.

## 데이터 범위

공통 SECURITY는 저장된 일봉이 있는 종목만 선택한다. 공통 RUN은 하나의 외부 전략 실행을 선택한다. 실행을 바꾸면 EXECUTION/RISK/OVERVIEW가 같은 run_id를 조회한다. 종목은 시장 스냅샷 기준이므로 실행의 데이터/시점과 같다고 가정하지 않는다. 화면의 시장 AS OF와 실행 보고 as_of를 각각 표시한다.

캔들은 수정 일봉 KRW, 20B/60B/ALL은 봉 수 범위다. hover에 날짜/OHLCV를 표시하고 x축 봉 간 간격은 동일하다. 변화율은 각 종목 최근 두 저장 일봉 대비이며 항상 전 거래일이라고 가정하지 않는다. 종목 표는 수집된 표본이며 전체 시장 등락·순위가 아니다.

선물/호가·금리/채권·외환/원자재는 아직 데이터가 없다. 계좌 NAV·손익·전략 기여도·대사는 별도 계좌 장부 데이터가 필요하다. 독립 전략 수익을 합산해 만들지 않는다. 리스크 미보고/unknown을 정상으로 바꾸지 않는다. 평가액 그래프의 통화는 현재 run 스키마에 없으므로 외부 단위 확인 필요 문구를 표시한다.

## 구현 경계

`web/terminal-ui.js`는 읽기 전용 화면과 공통 종목/실행 조회 함수, 캔들 렌더링을 담당한다. `web/app.js`는 context·명령·파일·데이터 모드와 DOM을 연결한다. 외부 결과는 기존 `runtime-ui.js`/관측 규격을 사용한다. 실행 엔진·브로커·리스크 정책은 이 UI에 추가하지 않는다.

Pages는 공개 시장 데이터와 탭 메모리의 결과 파일을 조회한다. 운영 DB/개인 보고는 정적 빌드에 들어가지 않는다. 비공개 레퍼런스의 API·계좌·전략 계약은 현재 API와 자동 호환되지 않는다. 실제 연동은 비공개 backend/실행 어댑터에서 범위·단위·시각 계약을 맞춰야 한다.
