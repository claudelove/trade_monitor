4. `pages-preview.js` is local compatibility code. It serves only the existing public snapshot and empty account/run lists. No private endpoint or credential is configured. Public disclosure details retain the known original record and mark source/receipt/availability clocks and canonical revision as unavailable. Snapshot dates are not promoted to canonical availability times.

`tests/pages.mjs` checks upstream byte parity for all untouched frontend files, disclosure clock honesty, empty accounts, no network writes/private requests, clean builds and deployed licenses. The old public controller/renderer is removed rather than kept as another product implementation. Old runtime-v1 APIs remain backend compatibility APIs; this UI uses the integrated engine contract.

## Updating again

Read the next private commit first, select only frontend/license paths, and review changes to API operations and static data. Update the pinned manifest and synthetic tests. Do not mirror the private repository or strategy folders. Regenerate the catalog and run:

```sh
python scripts/sync_screens.py --check
npm run test:ui
npm run test:pages
.venv/bin/python -m pytest -q
```

Then inspect actual browser rendering and native OHLCV, review the staged file list for private material, and push **only** public `work`. Inspect Actions and public `version.json`. The private repository remains the integrated engine/UI source; this repository publishes the reviewed frontend snapshot and public preview. Further engine work is not automatically authorized for public export.

Private hosting/authentication/real market/broker acceptance is separate. GitHub Pages does not run the engine, historical workers, access-policy or database services.
